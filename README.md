# MynaAuth

マイナンバーカードの利用者証明用電子証明書を用いた Windows サインインを行うソフトウェア。

**実物マイナンバーカードと Android 搭載電子証明書を自動判別して認証します。所有者による両方の動作確認後、Windows ログイン用 Credential Provider と設定アプリを追加しました。Windows への登録と実ログオン確認は、設定アプリでの資格情報・カード登録後に行います。**

## Windows ログイン画面の開発用ビルド

`scripts/Build-LogonBundle.ps1` でビルドし、`artifacts/MynaAuth-Logon/MynaAuth.Setup.exe` を起動します。アプリ上で Windows アカウント・Windows パスワード・許可するカード／スマホを登録してから、ログイン画面に追加します。Windows パスワードは許可された方式として DPAPI で暗号化・アクセス制限して保持し、カード／スマホの PIN は保存しません。標準のパスワード／Windows Hello は残します。

導入・削除・保護方式・未検証事項は [Windows ログイン手順](docs/windows-logon.md) を参照してください。Windows パスワードはチャットやコマンド引数へ記載せず、設定アプリにだけ入力してください。

## デスクトップアプリ

64-bit Windows、.NET 8 Desktop Runtime、64-bit 版 JPKI 利用者ソフト、RC-S300 のドライバーが必要です。JPKI ソフトの IC カードリーダライタ設定で使用するリーダーを選択してください。SDK から起動する場合:

```powershell
dotnet run --project src/MynaAuth.Desktop
```

- **自動（カード／Android・初期選択）**: かざす媒体に対応する利用者証明用 PIN 数字4桁を入力 → 「カード提示へ」 → カードまたは Android を1つだけかざす → 自動判別して認証。判別時は公開の種類名だけを読み、PIN を送る前に認証経路を決めます。カード用とスマホ用の PIN は異なる場合があります。
- **Android で認証（試験）**: スマホ用の利用者証明用 PIN 数字4桁を入力 → 「カード提示へ」 → NFC 有効・ロック解除済みの S25 を RC-S300 にかざす → 認証結果。実物カードはリーダーから離してください。スマホ用 PIN はカード用 PIN や端末のロック解除 PIN とは別です。
- **マイナカードで認証**: 実際の利用者証明用 PIN 数字4桁をアプリ上で入力 → 「カード提示へ」 → 実物カードを RC-S300 に置く → 認証結果。結果が出るまでカードを動かさないでください。署名用の6〜16桁のパスワードは使用しません。
- **模擬認証**: 操作確認用の数字4桁 → カード提示画面 → 「模擬カードをかざす」 → 模擬署名の検証結果。実際の PIN は使いません。
- **実機の提示を検出**: 操作確認用の数字4桁 → RC-S300 上を一度空にする → カードをかざす → 提示の検出結果。入力値はカードへ送信しません。カードの種類や本人性を検証する機能ではありません。

実カード用 PIN はアプリにのみ入力し、チャット・コマンド引数・設定ファイルへ記載しないでください。PIN は1回だけ照合し、自動再送しません。3回連続で誤るとカード側でロックされます。誤入力結果が出たら正しい番号を確認してください。

実カードモードは毎回新しい乱数に対する RSA / SHA-256 署名を検証し、公式の利用者証明用認証局への信頼・証明書の期限・鍵用途も検証します。**オンライン失効確認は行いません。** また、特定の Windows アカウントや登録済み所有者との対応付けは行いません。有効なカードと PIN を提示できることのローカル検証です。

入力・カード証明書・署名は保存しません。PIN は照合直後、その他のバッファは完了時に消去し、セッションを解放します。カード待ちは最大60秒、キャンセル／やり直しが可能です。既に実行中のネイティブ関数を強制停止せず、その呼び出し終了後にキャンセルを反映します。

Android 経路では Windows の PC/SC API で JPKI アプリと公開の種類名を選択・確認してから PIN を1回だけ送信します。既存の物理カード用 PKCS#11 ライブラリで Android の種類が拒否される問題を避ける専用の試験経路です。PIN 後は同じ発行元・期限の検証と RSA / SHA-256 のチャレンジ応答検証を行います。ロック解除だけを生体認証済みの証拠として扱わず、PIN を保存して生体認証で再利用することもしません。

認識エラーを調べられるように、失敗した処理名（固定の列挙値）・数値エラーコード・UTC 時刻だけをアプリと同じフォルダーの `diagnostics.log` に記録します。直近の1件で上書きし、PIN、カード番号、証明書、署名、例外本文や通信データは含めません。画面にも同じエラー番号を表示します。成功は記録しないため、成功後に残っているログは以前の失敗です。

自動判別の更新版アプリ一式は `artifacts/MynaAuth-Auto/` に出力します。起動は同フォルダーの `MynaAuth.Desktop.exe`。配布時は exe 単体ではなく、同じ出力フォルダーの依存ファイルも必要です。JPKI の DLL は同梱せず、実物カードではインストール済みの公式ライブラリを読み込みます。

画面遷移の検証は `dotnet run --project tests/MynaAuth.Desktop.Checks`。このチェックは自分のテストウィンドウだけを操作し、模擬の画面画像を `artifacts/` に出力します。実カードへの PIN 送信や Windows 設定の変更は行いません。

実カード用処理の合成データによる検証は `dotnet run --project tests/MynaAuth.Jpki.Checks`。`-- --native-preflight` を付けると、実際の JPKI ライブラリの初期化・スロット列挙と、カードが1枚ある場合のカード情報確認・セッション開始までを確認します。PIN は送信せず、証明書も読みません。`-- --pcsc-link` は Windows 標準 API の接続確立だけを確認します。開発者の自動テストでは実カードでの認証成功は未確認です。

## 現在動かせるもの

.NET 8 SDK 以降を使用します。外部 NuGet パッケージは不要です。

```powershell
dotnet run --project src/MynaAuth.Probe -- --simulate
dotnet run --project src/MynaAuth.Probe -- --readers
dotnet run --project tests/MynaAuth.Checks
```

模擬アプリは任意の数字4桁を入力して Enter、その後 Enter でカード提示を模擬します。Esc で終了します。実カードの PIN を入力しないでください。模擬用鍵は起動時に生成し、保存しません。

`--readers` は Windows の PC/SC リーダー名を表示します。カードへの接続・PIN 送信・証明書の読み取りは行いません。RC-S300 の接続確認に利用できます。表示される名前から本体の型番やスマホ対応までは判定できません。

Core は模擬認証用の登録済み公開鍵による検証です。実カードモードは別の Jpki プロジェクトが公式 PKCS#11 ライブラリを呼び出します。どちらも PIN は ASCII 数字4桁に限定します。

## 開発用管理者

管理者権限の **64-bit Windows PowerShell** で、まずプレビューします。

```powershell
.\scripts\New-DevelopmentAdmin.ps1 -WhatIf
.\scripts\New-DevelopmentAdmin.ps1
```

スクリプトは専用ローカル管理者を作成します。パスワードは対話入力し、ファイルやコマンド引数に保存しません。既存アカウントは変更しません。現在の Microsoft アカウントとは別です。

作成後にユーザー切り替えで復旧アカウントへ実際にパスワードサインインできることを確認してください。この開発用アカウントの作成・確認は任意で、登録画面の必須手順ではありません。復旧用パスワードはリポジトリ外の安全な場所に保管します。

## 次の実装に必要なもの

- 所有者による実カード認証の動作確認。
- 自動判別後の実物カード経路の実機確認。
- オンライン失効確認と、保護された公開鍵・Windows SID の登録処理。
- Microsoft アカウントの Windows 認証へ橋渡しする方式の決定。カードの署名をパスワードとして送信してもログインできません。
- V2 Credential Provider、権限を限定したサービス、認証済み IPC、導入・削除・復旧手順と仮想環境でのログオン試験。

詳細と調査元は [設計メモ](docs/architecture.md) を参照してください。

## 機密情報

マイナンバー、氏名・住所、PIN、Windows パスワード、実証明書、証明書のシリアル番号、個人に結びつくログ・画像を README、設定サンプル、テスト、Issue に含めません。`.gitignore` は補助であり、共有前に内容を確認してください。公開鍵の登録データも個人との対応を含むため、リポジトリには保存しません。

`src/MynaAuth.Jpki/Roots/` の2ファイルは JPKI が公開する認証局の証明書で、利用者の証明書ではありません。公式の SHA-256 フィンガープリントとの一致を実行時にも確認します。診断ログは上記の固定項目だけで、個人証明書の保存・通信ダンプ・ネットワーク送信は実装していません。OS、デバッガー、外部 JPKI ソフトによるメモリダンプや記録までこのアプリだけで制御することはできません。
